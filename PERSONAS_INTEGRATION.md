# Personas Integration - HCI Alignment

**Date**: 2026-01-25
**Motivation**: Critical gap identified - personas are missing from UX workflow
**Alignment**: SENG2260 HCI principles (diverse users, evaluation, iterative design)

---

## Problem Identified

The initial SDLC plugin implementation lacked a **persona system**, which caused:

1. ❌ **No foundation for user-centered design** - artifacts created without specific users in mind
2. ❌ **Generic "user" trap** - requirements and journeys assumed abstract users
3. ❌ **No evaluation strategy** - unclear who to test with or how to select participants
4. ❌ **No traceability** - journeys, requirements, tests not linked to actual user needs
5. ❌ **No diversity consideration** - accessibility and inclusion treated as afterthoughts
6. ❌ **Non-HCI-course-compliant** - missing core HCI concepts (personas, evaluation planning)

---

## Solution Implemented

### 1. Source of Truth: `sdlc.state.json`

**Location**: `docs/sdlc.state.json` (generated by `/sdlc:init`)

**Purpose**: Single source of truth for:
- ✅ All personas (with full details)
- ✅ All user journeys (persona-scoped)
- ✅ Evaluation participants and sessions
- ✅ Requirements linkages

**Schema**: Fully typed JSON Schema (`sdlc.state.schema.json.template`)

**Example Persona**:
```json
{
  "id": "sarah-pm",
  "name": "Sarah Chen",
  "role": "Project Manager",
  "goals": [
    "Track project progress efficiently",
    "Communicate status to stakeholders",
    "Identify and mitigate risks early"
  ],
  "painPoints": [
    "Scattered information across tools",
    "Manual status report generation"
  ],
  "capabilities": {
    "technicalExpertise": "intermediate",
    "timeAvailable": "15-30 min per session"
  },
  "accessibility": {
    "visualNeeds": "None (wears reading glasses)",
    "assistiveTech": []
  },
  "topTasks": [
    {
      "id": "view-status",
      "description": "View overall project status",
      "frequency": "daily",
      "importance": "critical"
    }
  ],
  "quote": "I need to see the big picture without drowning in details."
}
```

**File**: `skills/plan/templates/persona-template.md`

**Sections**:

9. Related Artifacts (links to journeys, requirements, evaluation)

### 3. Evaluation Planning Template

**File**: `skills/plan/templates/evaluation-plan-template.md`

**Comprehensive Coverage**:

#### Participant Selection
- Maps personas → evaluation participants
- Selection criteria per persona
- Recruitment plan and timeline
- Practical constraints (budget, schedule)

**Example**:
| Persona | Count | Criteria | Budget |
|---------|-------|----------|--------|
| Sarah (PM) | 3-5 | 5+ years PM experience | $50 × 4 = $200 |
| Dev (Engineer) | 3-5 | Software developers | $50 × 4 = $200 |
| Alex (End User) | 5-7 | Non-technical users | $50 × 6 = $300 |
| **Total** | **12-17** | | **$700** |

#### Ethics & Informed Consent

**Mandatory Elements**:
- ✅ Participant information sheet
- ✅ Consent form (signature required)
- ✅ Right to withdraw explained
- ✅ Data handling and anonymization
- ✅ Ethics approval (if institution requires)

**Checklist Format**: Easy to verify compliance

#### Session Protocols

**Walkthrough Scripts** for each persona-scoped journey:
1. Pre-session (10 min): Welcome, consent, explain think-aloud
2. Session (30-45 min): Warm-up + main tasks + observation
3. Post-session (10 min): Debrief, questionnaire, incentive

**Deliverables**:
- Task scripts
- Note-taking templates
- Success criteria (measurable)

#### Iterative Testing Cycles

**3 Cycles** matching prototype fidelity:
- **Cycle 1: Low-fi** (sketches) → Validate concept
- **Cycle 2: Med-fi** (clickable) → Refine interactions
- **Cycle 3: High-fi** (coded) → Polish details

**Success Metric**: Improvement across cycles (e.g., task completion 60% → 80% → 95%)

#### Heuristic Evaluation Checklists

**Nielsen's 10 Usability Heuristics**:
- Visibility of system status
- Match system and real world
- User control and freedom
- Consistency and standards
- Error prevention
- Recognition rather than recall
- Flexibility and efficiency
- Aesthetic and minimalist design
- Help users recognize/diagnose/recover from errors
- Help and documentation

**WCAG 2.1 AA Accessibility**:
- Perceivable
- Operable
- Understandable
- Robust

**As** [Sarah (Project Manager)] - Persona: `sarah-pm`

## HCI Course Alignment (SENG2260)

### ✅ Understanding Users

**Concept**: Know your users (not "generic user")

**Implementation**:
- Personas created FIRST in workflow
- 2-5 specific personas (not abstractions)
- Demographics, goals, context, constraints
- Diversity built in (expertise, accessibility)

**Evidence**: `docs/sdlc.state.json` personas array

### ✅ Design to Fit

**Concept**: Design for diverse user populations

**Implementation**:
- Each persona has accessibility considerations
- Range of technical expertise (novice → expert)
- Different contexts (desktop, mobile, assistive tech)
- Cognitive load and time constraints captured

**Evidence**: Persona `accessibility` and `capabilities` fields

### ✅ Evaluation Planning

**Concept**: Select representative users for evaluation

**Implementation**:
- Participant selection explicitly mapped to personas
- Practical constraints (budget, schedule) documented
- Recruitment criteria per persona
- Ethics and informed consent framework

**Evidence**: `docs/ux/evaluation-plan.md`

### ✅ Pre-Planned Scenarios

**Concept**: Walk through scenarios noting issues

**Implementation**:
- Every journey is persona-scoped
- Success criteria defined upfront (measurable)
- Walkthrough scripts prepared per journey
- Issue tracking per step

**Evidence**: `sdlc.state.json` journeys with `successCriteria` and `steps[].issues`

### ✅ Iterative Prototyping

**Concept**: Test → Improve → Retest

**Implementation**:
- 3 evaluation cycles (low-fi → med-fi → high-fi)
- Measurable improvement tracked
- Findings fed back into design

**Evidence**: `evaluation-plan-template.md` iterative cycles section
